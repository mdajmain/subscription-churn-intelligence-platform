# Model card — subscription churn risk model

Step 8.3. Intended as the single place someone decides whether to trust
this model enough to act on it — and, as much as the results above it,
what it does *not* establish.

## Intended use

Ranks currently-active subscribers by predicted probability of churning
within 30 days of their next renewal cutoff, for a retention team to
prioritize outreach — either by probability alone or by revenue exposure
(`calibrated_probability x expected_next_renewal_value`, see README.md's
Week 6.1 section). It is a **prioritization tool**, not a decision-maker:
it ranks who to look at first, it does not decide what to do about them,
and it has never been evaluated against the outcome of any retention
action (see "What this model does not establish" below).

**Not intended for:** estimating aggregate revenue at risk as a company-
wide forecast (the exposure metric is a per-subscriber ranking signal,
not a validated forecasting model), any use on real KKBox subscribers
(trained entirely on synthetic data — see "Training data" below), or any
automated action taken without a human reviewing the case.

## Training data and window

Synthetic data generated by `ingest/generate_synthetic_data.py` (6,000
simulated users, registrations 2015-01 through 2016-06, transactions
through 2018-05) — **not real KKBox subscriber data**. See README.md's
"Data source" section for the full reasoning; the short version is that
this project could not download the real ~30GB dataset, so a generator
reproduces the same schema and the same eight known data-quality issues
instead. Every finding below describes this simulated population's
mechanics, which is partly a function of the generator's own design
choices (hazard function, decay ramp) — read these as evidence the
*pipeline* can detect known-injected signal, not as claims about real
subscriber behavior.

Time-based split (`models/train.py`): train through 2016-11-30 (33,820
rows, 8.1% churn), validation December 2016 (1,552 rows, 7.4% churn),
test January-February 2017 (2,842 rows, 6.1% churn, reported once). No
row's label uses data at or after its own `cutoff_date` — enforced by an
automated test (`tests/test_no_leakage.py`) that also verifies the test
would actually fail under a leaky `<=` cutoff, not just pass vacuously.

## Features

24 features in `fct_features`/`fct_prediction`, all computed with a
strict `< cutoff_date` filter: subscriber attributes (city, age band,
gender, registration channel, tenure), current plan (length, price,
amount paid, discount, auto-renew, payment method), prior transaction
history (renewal/cancellation/plan-change counts), and 7/30/90-day
activity windows (total playback seconds, active days, unique tracks,
days since last activity, play-quality ratios). Full list and derivation:
`sql/build_features.sql` / `dbt/models/marts/fct_prediction.sql`.

A parallel experiment (`models/train_sequence.py`, README.md Week 5) fed
the raw 90-day daily activity sequence to a GRU instead of these windowed
aggregates, and lost (PR-AUC 0.543 vs. 0.652) — evidence the windowed
aggregates already capture the signal that matters for this population.

## Model

Gradient-boosted trees (XGBoost), hyperparameters tuned via Optuna (30
trials against validation PR-AUC) — `models/xgb_best_params.json`.
Compared in order against a rule baseline (`is_auto_renew=0`) and a
regularized logistic regression before XGBoost was selected
(`models/train.py`).

## Performance (test set, reported once)

| model | PR-AUC | ROC-AUC | precision@5% | recall@5% | Brier |
|---|---|---|---|---|---|
| rule baseline (`is_auto_renew=0`, full rule) | — | — | 0.111 | 0.741 | — |
| logistic regression | 0.531 | 0.894 | 0.570 | 0.466 | 0.039 |
| **XGBoost (selected)** | **0.651** | **0.932** | **0.676** | **0.552** | **0.035** |

Lift over rule baseline at top-5% review capacity: 4.50x (logistic
regression), 5.33x (XGBoost). Test-set base rate is 6.1% — a real lift
over both the rule and a coin flip, not a suspiciously-perfect number.

**A version note, stated rather than smoothed over:** this table is from
the original Week 3 training run (`notebooks/07_model_results.md`).
`models/score_predictions.py` (Week 6) refit the same model with the same
tuned hyperparameters on an environment where `scikit-learn`/`xgboost`
had drifted to newer versions (a real dependency-pin drift found and
fixed this project, see `CLAUDE.md`'s Week 6/7 entries) and got PR-AUC
0.6646 on the identical test rows — a few points higher, most plausibly
from library-version differences in XGBoost's tree-building rather than
any change to the data or method. Both numbers are reported here rather
than picking one silently; **0.6646 / Brier 0.0337 (after calibration,
below) is what's actually live** in `model_predictions` and the API.

### Segment breakdown (original Week 3 run)

| segment | n | churn rate | PR-AUC |
|---|---|---|---|
| plan_days=7 | 122 | 6.6% | 0.386 |
| plan_days=30 | 1,860 | 5.5% | 0.642 |
| plan_days=90 | 465 | 7.7% | 0.746 |
| plan_days=180 | 231 | 7.4% | 0.684 |
| plan_days=410 | 164 | 6.7% | 0.590 |
| tenure 91-365d | 930 | 6.2% | 0.591 |
| tenure 365d+ | 1,912 | 6.1% | 0.680 |

The model is markedly weaker on 7-day plans (PR-AUC 0.386, n=122) than
on any other plan length — the smallest segment by count, so this could
be a genuine harder-to-predict population or simply noisier from a small
n; not disentangled here. **Practical implication: treat this model's
output for 7-day-plan subscribers with more skepticism than for 30/90-day
plans**, where most of the volume (and the best PR-AUC) sits. No
test-period segment exists below ~7 months' tenure — a property of the
generator's fixed registration window, not a finding (see "Known failure
modes").

## Calibration

Isotonic calibration (more flexible) was tried first and **measurably
hurt ranking** on this validation set (PR-AUC 0.6646 -> 0.6239, n=1,552 —
too small for isotonic's piecewise-constant fit not to overfit). Sigmoid
(Platt) scaling was used instead: improves Brier (0.0342 -> 0.0337) while
leaving PR-AUC exactly unchanged. Full comparison:
`notebooks/10_calibration_check.md`. This matters concretely: the
revenue-exposure metric (README.md Week 6.1) multiplies this calibrated
probability by expected renewal value, so a badly-calibrated probability
would silently bias which subscribers look most valuable to review.

## Known failure modes

- **7-day-plan subscribers**: PR-AUC 0.386 vs. 0.6-0.75 elsewhere (see
  segment table) — smallest segment, weakest signal.
- **No sub-7-month-tenure test cases**: the synthetic registration window
  (Jan 2015 - Jun 2016) means no test-period subscriber can have under
  ~7 months' tenure — a real limitation of this specific synthetic
  dataset, not a property of real subscriber populations, and not
  something this model has been checked against.
- **Right-censoring near the data boundary**: any snapshot whose 30-day
  label window hasn't fully elapsed against `max(transaction_date)` is
  excluded from training/eval (`fct_snapshot.label_censored`) — but
  `model_predictions` scores censored rows too (by design, so a currently-
  active subscriber always has a risk score), meaning some scored rows
  have no ground truth to ever check them against.
- **Calendar drift**: the naive churn rate drifts from ~27% (early 2015)
  to ~38-41% (late 2016) with a Nov-Jan seasonal bump
  (`notebooks/03_churn_rate_over_time.md`) — a test-window performance
  number can partly reflect the test window's own base rate, not model
  skill. The reported PR-AUC is against the actual 6.1% test base rate,
  not an inflated one, but future drift beyond the training window is
  unchecked.
- **Sequence information is genuinely not used**: the Week 5 experiment
  showed a GRU over raw daily activity loses to the windowed aggregates
  this model uses — a negative result, but also a stated boundary: if
  churn dynamics in a deployed population depend on fine-grained
  day-to-day pattern (bursty vs. steady use, not just recency/level),
  this model has no mechanism to see it.

## What this model does not establish

- **No causal claims.** Every finding in this project (tenure risk, plan
  length, activity decay) is an observational association. Plan choice,
  tenure, and engagement are not randomly assigned; the model has not
  been evaluated in any setting where an intervention was actually run.
- **No evidence about intervention effectiveness.** "Revenue at risk" is
  `probability x value`; it is explicitly **not** "revenue that would be
  saved" by any retention action, because no retention action has been
  taken and measured against this population. Acting on this model's
  output and measuring the outcome would be a different, unbuilt project.
- **No evidence this generalizes to real KKBox subscribers**, or to any
  real subscription business — see "Training data" above.
- **No evidence beyond the observed 6.1% test base rate and Jan-Feb 2017
  window.** Performance under a meaningfully different churn base rate,
  season, or subscriber mix has not been measured.
